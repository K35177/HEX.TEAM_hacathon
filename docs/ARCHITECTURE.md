# Архитектура и протокол

## Компоненты

```text
CLI → File transfer → Packet protocol → FSK modem → WAV / audio device
                                                   ↓ acoustic channel
CLI ← File transfer ← Packet protocol ← FSK modem ← WAV / audio device
```

- **CLI** принимает команды и выводит состояние передачи.
- **File transfer** читает файл, формирует метаданные, разбивает данные на
  блоки и собирает принятые блоки.
- **Packet protocol** нумерует блоки и защищает каждый пакет CRC32.
- **FSK modem** представляет нулевой и единичный биты двумя частотами.
- **Audio layer** записывает WAV либо работает с динамиком и микрофоном.

## Физическое кодирование

Базовый профиль использует бинарную FSK:

- частота дискретизации: 48 000 Гц;
- скорость: 200 символов/с;
- бит `0`: 1200 Гц;
- бит `1`: 2200 Гц;
- порядок битов: от старшего к младшему;
- перед каждым пакетом будет передаваться известная преамбула для обнаружения
  сигнала и синхронизации границ символов.

Параметры намеренно консервативны. После получения устойчивого канала скорость
можно увеличить или перейти на 4-FSK.

## Формат пакета версии 1

Все целые числа записываются в network byte order (big-endian).

| Поле | Размер | Назначение |
|---|---:|---|
| Sync word (`HEXA`) | 4 байта | поиск начала пакета |
| Version | 1 байт | версия протокола |
| File ID | 4 байта | идентификатор передачи |
| Block index | 2 байта | номер блока с нуля |
| Block count | 2 байта | общее число блоков |
| Payload length | 2 байта | длина полезных данных |
| Payload | 0–65535 байт | данные блока |
| CRC32 | 4 байта | проверка заголовка и payload |

Для MVP payload будет ограничен 128 байтами. Первый логический пакет содержит
имя файла, размер и SHA-256. Каждый пакет надёжного профиля повторяется трижды;
приёмник принимает первую копию с корректным CRC и игнорирует дубликаты.

CRC32 обнаруживает повреждение отдельного пакета. SHA-256 подтверждает, что
после сборки получен исходный файл целиком.

## Синхронизация и состояние

Приёмник ищет преамбулу в непрерывном потоке, определяет начало символа,
декодирует заголовок, затем известное число байтов payload и CRC. Принятые
блоки сохраняются по `(file_id, block_index)`. Прогресс вычисляется по числу
уникальных корректных блоков.

Первая версия не требует обратного акустического канала: устойчивость даёт
тройное повторение блоков. ACK/NACK и адресная повторная передача являются
следующим уровнем развития.
