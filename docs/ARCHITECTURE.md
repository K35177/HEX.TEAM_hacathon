# Архитектура и протокол

Архитектура сохранена модульной:

```text
CLI / Tkinter UI
       ↓
Transfer metadata → packets/CRC32 → framing/chirp → FSK → WAV/audio backend
       ↑                                                        ↓
SHA-256/file      ← packet assembly ← frame detection ← FSK ← microphone/WAV
```

- **CLI/Menu** разбирает команды, обеспечивает безопасную работу с файлами и
  показывает прогресс.
- **UI** запускает тот же CLI и не дублирует протокол.
- **Profiles** загружает `config/*.conf` в существующие конфигурации FSK/frame.
- **Transfer layer** добавляет имя, размер и SHA-256, делит файл на блоки.
- **Packet protocol** нумерует блоки и защищает каждый пакет CRC32.
- **Framing** добавляет chirp, защитный интервал и длину потока.
- **FSK modem** преобразует символы в частоты и обратно.
- **Audio layer** работает с PCM WAV и платформенным аудио.

## Текущая операционная модель

Версия 0.5.0 работает как half-duplex one-shot transfer:

1. профиль вручную выбирается на обоих устройствах;
2. sender формирует весь transfer stream и один WAV;
3. receiver записывает фиксированный интервал целиком;
4. одна chirp-преамбула синхронизирует весь поток;
5. декодирование начинается после окончания записи;
6. при любой неисправимой ошибке вся попытка отклоняется.

Это важная граница текущей реализации, а не целевая модель. Protocol v2 должен
добавить independently framed packets и streaming state machine внутри
существующих слоёв. План описан в [ROADMAP.md](ROADMAP.md).

## Аудиобэкенды

| Платформа | Воспроизведение | Запись |
|---|---|---|
| Windows | Windows Multimedia `PlaySound` | Windows Multimedia `waveIn` |
| macOS | системный `afplay` | CoreAudio Audio Queue |
| Linux | ALSA `aplay` | ALSA `arecord` |

Публичный интерфейс аудиослоя одинаков на всех платформах. Однако Linux/macOS
backend ещё должны пройти end-to-end hardware matrix; наличие реализации не
следует трактовать как подтверждённую совместимость со всеми устройствами.

## Синхронизация и устойчивость

Перед данными передаётся линейный chirp и защитный интервал. Приёмник:

1. оценивает нижний процентиль фонового шума;
2. находит участок сигнала по RMS;
3. уточняет начало нормализованной корреляцией;
4. ищет растяжение/сжатие времени в диапазоне ±2%;
5. пересэмплирует payload к номинальным границам символов;
6. определяет FSK-тон с окном Hann и небольшим поиском частотного смещения.

Демодулятор использует Goertzel и формирует confidence/frequency metrics.
Совместный поиск chirp start/clock scale устраняет ошибку, при которой корреляции
с разным stride сравнивались напрямую. В тестовом simulator подтверждены AWGN,
clipping и clock scale до 4000 ppm; continuous tracking пока отсутствует.

Четыре байта после chirp задают длину transfer stream, поэтому хвост записи
может содержать тишину.

Автоматизированно проверено синтетическое рассогласование 0,8%. Это не означает
гарантированную коррекцию всех записей с рассогласованием до 2%.

## Метаданные передачи

Все многобайтные числа имеют big-endian порядок.

| Поле | Размер |
|---|---:|
| Magic `HXMD` | 4 байта |
| Version | 1 байт |
| Filename length | 2 байта |
| File size | 8 байт |
| SHA-256 | 32 байта |
| Filename | переменный |

## Пакет версии 1

| Поле | Размер |
|---|---:|
| Sync word `HEXA` | 4 байта |
| Version | 1 байт |
| File ID (CRC32 файла) | 4 байта |
| Block index | 2 байта |
| Block count | 2 байта |
| Payload length | 2 байта |
| Payload | определяется профилем |
| CRC32 заголовка и payload | 4 байта |

Приёмник требует последовательный полный набор блоков и проверяет пакетные CRC,
размер, общий CRC32 и SHA-256. Результат фиксируется на диске только после всех
проверок.

## Безопасность файлов

- временные WAV получают уникальные случайные имена;
- временные файлы очищаются через RAII;
- результат сначала записывается рядом как `.part-*`;
- сохранение без `--force` использует атомарную no-clobber фиксацию;
- имя принятого файла очищается от директорий;
- совпадающие имена в папке приёма получают номер копии.
