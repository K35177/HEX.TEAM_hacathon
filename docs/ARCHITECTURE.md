# Архитектура и протокол

## Поток данных

```text
Файл → метаданные → блоки/CRC32 → 4-FSK → chirp + WAV → динамик
                                                          ↓
Файл ← SHA-256/сборка ← пакеты ← 4-FSK ← поиск chirp ← микрофон
```

- **CLI/Menu** выбирает режим и показывает состояние операции.
- **Transfer layer** добавляет имя, размер и SHA-256, делит файл на блоки.
- **Packet protocol** нумерует блоки и защищает каждый пакет CRC32.
- **Framing** добавляет chirp-преамбулу, защитный интервал и длину потока.
- **FSK modem** преобразует символы в частоты и обратно.
- **Audio layer** работает с PCM WAV и Linux-командами `aplay`/`arecord`.

Компоненты изолированы: тесты передают данные через WAV без аудиоустройств, а
live-режим использует тот же протокол и модем.

## Физическое кодирование

Профиль по умолчанию использует 4-FSK:

| Символ | Биты | Частота |
|---:|:---:|---:|
| 0 | `00` | 1200 Гц |
| 1 | `01` | 1800 Гц |
| 2 | `10` | 2400 Гц |
| 3 | `11` | 3000 Гц |

- частота дискретизации: 48 000 Гц;
- скорость: 200 символов/с, то есть 400 бит/с до служебных данных;
- один символ занимает 240 сэмплов;
- доступен также 2-FSK для будущего robust-профиля.

Перед потоком передаётся chirp длительностью 250 мс от 700 до 5000 Гц и
защитный интервал 50 мс. Приёмник сначала оценивает шум, находит участок
сигнала и уточняет начало chirp корреляцией с эталоном. Следующие четыре байта
задают точную длину полезного потока, поэтому запись может содержать тишину до
и после передачи.

## Метаданные передачи

Все многобайтные числа имеют порядок big-endian.

| Поле | Размер | Назначение |
|---|---:|---|
| Magic `HXMD` | 4 байта | идентификация метаданных |
| Version | 1 байт | версия формата |
| Filename length | 2 байта | длина имени файла |
| File size | 8 байт | исходный размер |
| SHA-256 | 32 байта | итоговая проверка |
| Filename | переменный | исходное имя файла |

## Пакет данных версии 1

| Поле | Размер | Назначение |
|---|---:|---|
| Sync word (`HEXA`) | 4 байта | сигнатура пакета |
| Version | 1 байт | версия протокола |
| File ID | 4 байта | CRC32 всего файла |
| Block index | 2 байта | номер блока с нуля |
| Block count | 2 байта | общее число блоков |
| Payload length | 2 байта | длина данных |
| Payload | до 128 байт в MVP | данные блока |
| CRC32 | 4 байта | проверка заголовка и payload |

Приёмник требует последовательный полный набор блоков, проверяет CRC32 каждого
пакета, размер собранного файла, общий CRC32 и SHA-256. Файл записывается на
диск только после успешной проверки.

## Live audio

`send` создаёт временный WAV и воспроизводит его через `aplay`. `receive`
записывает mono 16-bit PCM WAV через `arecord`, после заданного интервала ищет
chirp и декодирует файл. Такой backend не требует сторонних C++-библиотек и
может быть заменён на PortAudio без изменений протокола.
